# Мультиплеер на Socket.IO

## Запуск

Требуется Node.js 22.7 или новее.

```sh
npm install
npm run dev
```

Команда запускает React на `http://localhost:3000` и сервер игры на порту `3001`. React проксирует `/socket.io` к серверу. Если React уже запущен, перезапустите его после изменения `package.json`, чтобы включился proxy.

Можно запустить процессы отдельно: `npm run server` и `npm start` в двух терминалах.

Готовая сборка обслуживается тем же сервером, что и сокеты:

```sh
npm run build
npm run server
```

Откройте `http://localhost:3001`. Для игры в одной сети друзья открывают адрес компьютера с сервером, например `http://192.168.1.10:3001`. Для игры через интернет разместите сервер на публичном хосте, который поддерживает WebSocket и постоянный Node.js-процесс. У обратного прокси должны проходить `/socket.io/` и обновление соединения до WebSocket.

## Комната и партия

1. Раскройте «Играть онлайн», выберите одного персонажа, введите ник и создайте комнату. До выбора подключение недоступно; нажатие на портрет открывает полную историю из `lore`.
2. Отправьте друзьям ссылку или шестизначный код. Если создатель открывает игру через `localhost`, сервер подставляет в приглашение адрес компьютера в локальной сети, сохраняя порт страницы. Устройства должны быть в одной сети. Для публичного хостинга можно явно задать `PUBLIC_ORIGIN`.
3. При первом входе по приглашению друг выбирает персонажа и вводит ник. Enter или «Войти в комнату» сразу подключает его к комнате из ссылки; повторно вводить код не нужно. При повторном открытии той же ссылки сохранённый вход и персонаж восстанавливаются автоматически. При первом входе без ссылки код вводится вручную. Места выдаются сервером, максимум их четыре.
4. Хозяин комнаты начинает партию, когда подключились минимум два игрока. До начала можно собрать двух, трёх или четырёх участников. Состав фиксируется при старте; новые участники после старта не добавляются. Отключённые места лобби при старте освобождаются и в партию не входят.
5. Бросать кубики и двигать фишки может только участник, чей сейчас ход. Поле, результат кубиков, СИЗО, подворотни, взятия и победа синхронизируются у всех.

Локальная игра за одним устройством доступна на главной странице без входа в комнату. Страница приглашения предназначена для подключения к онлайн-партии.

Для нового участника ссылка открывает отдельную форму с выбором персонажа и ником. При сохранённом входе вместо формы показывается восстановление подключения, затем открывается текущая партия. До входа поле и локальная партия скрыты. Карточки показывают реальные ники, выбранные портреты и состояния участников; очередь ходов содержит только участников текущей партии. В партии на двоих карточки расположены по бокам поля, на телефоне — рядом над полем. Пустые масти приглушены, их фишек в игре нет. В лобби дополнительные свободные места остаются доступными для приглашений и не мешают начать вдвоём.

Персонаж закрепляется за местом при первом входе и сохраняется при новой партии. Каждый участник выбирает ровно один `characterId`; одинаковый персонаж у разных участников допускается. Цвет игрового места выдаётся отдельно. Истории и семь портретов берутся из `lore`, общий каталог браузера и сервера — `src/shared/characters.js`. Он обновляется командой `npm run characters`, которая также выполняется перед запуском и сборкой. Выбор при восстановлении не запрашивается и не принимается заново от клиента.

При открытии приглашения из окна создателя в отдельном окне новый участник вводит свой ник; скопированный браузером активный сеанс создателя не занимает его место. Обычное повторное открытие ссылки сохранённым участником восстанавливает его место, включая случай, когда старое соединение ещё активно. Обновление страницы также восстанавливает сеанс. Приглашение в другую комнату открывает указанную комнату, даже если вкладка раньше участвовала в другой партии. На HTTP-адресе локальной сети копирование использует резервный механизм; если браузер запрещает копирование, поле со ссылкой выделяется для ручного копирования.

## Соединение и срок хранения

- Активный сеанс хранится в `sessionStorage` текущей вкладки. Обновление страницы и временный обрыв связи возвращают того же игрока на то же место с полным состоянием партии.
- Резервный секрет входа сохраняется в `localStorage`; записи старше семи дней не используются. После закрытия вкладки откройте прежнюю ссылку или главную страницу в том же браузере и на том же адресе игры: вход восстановится автоматически, без выбора имени, кнопки возврата или повторного ввода ника. Ссылка восстанавливает собственное место именно в указанной комнате, главная страница — последний сохранённый доступный вход. Перед восстановлением сервер проверяет секрет; недоступные места удаляются из сохранённых входов.
- Пока сохранённый вход проверяется или сервер недоступен, форма нового ника скрыта. При восстановлении связи возврат продолжится автоматически; можно нажать «Подключиться сейчас». Явный выход удаляет текущий сохранённый вход и оставляет игрока вне комнат до следующего входа или открытия игры.
- Закрытие окна сразу сообщает об отключении остальным участникам. Для незаметного обрыва транспорта сервер отправляет heartbeat каждые 3 секунды и ждёт ответ до 5 секунд: обнаружение обычно занимает до 8 секунд. Клиент повторяет подключение с задержкой от 0,5 до 3 секунд; после восстановления сети возвращается автоматически. Кнопка «Подключиться сейчас» позволяет начать попытку вручную.
- Второе окно с тем же секретом заменяет прежнее соединение. Обычный новый участник не может занять чужое место или подставить цвет игрока.
- При отключении участника начавшаяся партия приостанавливается. Появляются уведомление с ником, красный статус на карточке и пауза поверх доски. Уже начатый бросок завершается сервером; новые действия ждут возвращения всех игроков. Возврат отмечается отдельным сообщением, после чего партия продолжается с прежнего состояния.
- В лобби место отключившегося участника резервируется на 60 секунд. В начавшейся партии место сохраняется до возврата, перезапуска или удаления комнаты.
- Если хозяин отключился, управление комнатой переходит первому подключённому участнику.
- «Новая партия» доступна хозяину: все возвращаются в лобби, отключившиеся места освобождаются.
- Явное нажатие «Выйти» во время партии возвращает оставшихся участников в лобби. Следующая партия доступна, если осталось хотя бы два подключённых игрока; если один — нужно пригласить ещё одного.
- Полностью опустевшая комната удаляется через 30 минут. Состояние хранится в памяти одного серверного процесса: перезапуск сервера удаляет комнаты.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SOCKET_PORT` / `PORT` | `3001` | Порт HTTP и Socket.IO; `SOCKET_PORT` имеет приоритет. |
| `HOST` | `0.0.0.0` | Адрес прослушивания сервера. |
| `PUBLIC_ORIGIN` | Автоматически | Публичный HTTP(S)-адрес игры для приглашений, например `https://game.example.com`. Если не задан, публичный адрес страницы сохраняется, а `localhost` заменяется на доступный адрес локальной сети. |
| `CLIENT_ORIGIN` | Все origins | Разрешённые origins через запятую, например `https://game.example.com`. Ограничение применяется к polling и WebSocket. |
| `REACT_APP_SOCKET_URL` | Origin страницы | Отдельный адрес сокет-сервера, если фронтенд и сервер размещены отдельно. Задаётся до сборки React. |

`GET /health` возвращает статус процесса и число комнат. Токены игроков и игровое состояние в этом ответе не публикуются.

## Протокол

Все запросы требуют acknowledgement. Успех: `{ ok: true, ... }`; отказ: `{ ok: false, error: { code, message } }`. Снимок комнаты может сопровождать ответ.

| Событие клиента | Данные |
| --- | --- |
| `room:create` | `{ name, characterId, pageOrigin? }` |
| `room:join` | `{ code, name, characterId, pageOrigin? }` |
| `room:resume` | `{ code, token, pageOrigin? }` |
| `room:recover` | `{ sessions: [{ code, token }] }`, максимум 16 сохранённых входов |
| `room:start`, `room:restart`, `room:leave` | `{}` |
| `game:command` | `{ id, revision, type, tileIndex?, pieceIndex?, rollId? }` |

Типы игровых команд: `roll`, `place`, `move`, `skip`. Переданный клиентом результат кубиков, цвет или готовое игровое состояние игнорируются. Сервер получает цвет из подтверждённого места сокета, проверяет очередь, фазу комнаты, допустимость действия и актуальную ревизию. Результат броска выбирается `crypto.randomInt(1, 7)`.

`characterId` — одна строка из каталога: `cashback`, `epstein`, `archiver`, `gazelov`, `katalonets`, `ayran`, `mafioznik`. Пропущенный, неизвестный ID или массив персонажей получает `BAD_CHARACTER`; комната или место при этом не создаются. Персонаж входит в публичный список игроков и ответ `room:recover` как `characterId`. `room:resume` возвращает прежнего персонажа из серверного места, игнорируя попытку заменить его в запросе.

`pageOrigin` сообщает origin страницы для формирования приглашения и не влияет на права игрока. Успешные ответы создания, входа и восстановления содержат `inviteOrigin`: адрес приглашения или `null`, если нужно использовать адрес страницы. Он не входит в публичный снимок комнаты.

Необязательный `pieceIndex` выбирает конкретную фишку текущего игрока: индекс 0–3 в постоянном массиве его фишек. Для `place` она должна находиться в руке; для `move` — на указанной `tileIndex` и иметь допустимый ход. Старые команды без индекса выбирают первую подходящую фишку. Перетаскивание отправляет тот же тип команды, что и кнопка; правила и выбранная клетка назначения рассчитываются сервером. Анимации запускаются на каждом клиенте после подтверждённого изменения состояния. Обновление серверного обработчика требует перезапуска Node-процесса, который удаляет комнаты из памяти.

`room:state` рассылает полный снимок только участникам комнаты: код, ревизию, фазу, хозяина, публичный список мест, признак паузы и состояние игры. У каждого места есть `characterId`, `connected` и `disconnectedAt` (время отключения или `null`). `notice` содержит последнее событие присутствия: уникальный `id`, `type` (`joined`, `disconnected`, `reconnected`, `left`), `playerId`, `name`, `color` и `at`. Секреты восстановления и внутренние socket IDs в снимок не входят. Повторный идентификатор команды не выполняет действие второй раз; устаревшая ревизия получает `STALE_STATE` и актуальный снимок.

`room:recover` проверяет секреты сохранённых входов, не подключая игрока к комнате. Ответ `sessions` содержит только подтверждённые места: `roomCode`, `playerId`, `name`, `characterId`, `color`, `connected`, `phase`. Токены не возвращаются и не попадают в Redux, приглашения или публичные снимки. Отсутствующие комнаты и недействительные секреты пропускаются. Для входа на найденное место клиент использует обычный `room:resume`.

Клиентские таймеры завершают только локальную анимацию. Общий бросок заканчивает серверный таймер; участник текущего хода может явно пропустить анимацию, сохранив выпавшие значения. На новом соединении состояние перечитывается целиком, поэтому восстановление не зависит от доставки всех пропущенных событий.

Одна и та же игровая логика используется браузером для локальной партии и сервером для онлайн-партии: `src/store/gameSlice.js` и `src/store/logic/`. Копии правил для сервера нет.

Справочник используемого транспорта: [Socket.IO Server API](https://socket.io/docs/v4/server-api/), [доставка событий и acknowledgements](https://socket.io/docs/v4/delivery-guarantees/), [настройки heartbeat сервера](https://socket.io/docs/v4/server-options/#pinginterval), [настройки переподключения клиента](https://socket.io/docs/v4/client-options/#reconnection).
